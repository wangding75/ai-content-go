# Iteration 8 PRD：数据录入与指标看板

## 1. 功能概述

本次迭代建立项目工作区内的指标中心，围绕“已发布内容的数据录入、指标查看、趋势观察和缺失提醒”形成闭环。用户可以先定义并查看指标模板，再为已发布内容录入或批量导入指标数据，在项目工作区查看指标汇总和趋势，并对缺失数据进行补录。

本次迭代的核心目标是沉淀稳定、可查询、可审计的 `MetricRecord` 数据输入，为后续策略建议能力提供可靠数据来源；本迭代不直接生成策略建议，也不实现自动平台采集。

## 2. Functional Requirements

### 指标模板与口径管理

- **FR-001（P0）查看指标模板列表**  
  用户可以按内容类型、平台和启用状态查看指标模板列表，列表展示指标编码、指标名称、单位、值类型、聚合方式、统计周期、是否必填和是否启用。无数据时展示空状态；请求失败时展示统一错误信息和 request_id。

- **FR-002（P0）创建指标模板**  
  用户可以新增指标模板，至少录入内容类型、平台、指标编码、指标名称、单位、值类型、聚合方式、统计周期和是否必填。创建成功后返回指标模板标识，并可在后续录入时被选择。缺少必填字段、指标编码重复或口径不合法时，系统返回校验错误，不创建模板。

### 指标录入与批量导入

- **FR-003（P0）手工录入单条指标**  
  用户可以为已发布内容手工录入单条指标，录入时必须能关联项目、内容单元、内容版本、发布任务、发布目标、平台、外部链接、指标编码、指标日期、周期、原始值、来源类型和来源引用。来源类型至少支持 `manual`、`import`、`extension`、`external_callback`；本迭代只要求 `manual` 与 `import` 完成闭环，其余来源类型作为后续自动采集兼容口径。录入成功后返回指标记录标识和标准化值。若关联发布对象不存在、指标模板不存在或未启用、字段格式不合法或值类型与模板定义不一致，系统返回统一错误。

- **FR-004（P0）批量导入指标**  
  用户可以一次提交多条指标记录进行批量导入，并查看成功数量、失败数量和逐条失败原因。批量导入不得因单条失败吞掉整批错误上下文。完全无有效记录时，系统返回失败结果并明确错误原因。

- **FR-005（P0）处理重复录入与幂等提交**  
  当用户针对同一项目、平台、发布目标、内容版本、指标编码、指标日期和周期重复提交指标时，系统必须保证不会产生多条冲突记录。相同请求重复提交应返回一致结果；同一唯一粒度但数值冲突时，系统返回冲突错误并提示用户改走后续修正流程。

- **FR-006（P1）查看指标录入记录**  
  用户可以按项目、平台、发布目标、内容单元、指标编码和日期范围查看指标记录列表，列表支持分页、筛选和排序。列表需展示核心关联信息、原始值、标准化值、来源类型、采集时间和最近更新时间。无数据、加载中和失败场景均需有明确反馈。

- **FR-007（P1）修正已录入指标并保留审计**  
  本迭代不要求提供独立的指标修正页面；但如果通过录入流程、导入流程或后端接口支持修正已录入指标，系统必须保留修正前后值、修正原因和操作者痕迹，至少能够在日志中追踪本次修正行为。若修正请求缺少必要说明或目标记录不存在，系统返回错误并保持原记录不变。

### 项目工作区指标表现

- **FR-008（P0）查看项目指标汇总**  
  用户可以在项目工作区的“指标表现”页面查看指定时间范围内的指标汇总结果，支持按平台、发布目标和指标编码筛选。汇总结果需展示指标值、所用聚合口径、来源记录数量和稳定汇总快照标识或等价可复现结果引用，并可区分“暂无数据”与“请求失败”。该汇总结果必须能作为后续策略建议的稳定输入，而不是只依赖前端临时计算。

- **FR-009（P0）从项目导航进入指标页面**  
  用户必须能从项目详情或项目工作区导航进入“指标表现”“指标录入”“趋势图”“缺失数据提醒”页面，页面刷新后仍可直接访问并保持导航高亮或当前位置提示，不允许核心页面只能通过手输 URL 打开。

### 趋势图与缺失提醒

- **FR-010（P0）查看指标趋势序列**  
  用户可以查看某个指标在指定时间范围内按日、周或月分桶的趋势序列，并看到缺失点标记。趋势图不得把缺失数据直接当作 0 展示；当没有符合条件的数据时，页面展示空状态说明。

- **FR-011（P0）查看缺失数据提醒**  
  用户可以查看已发布内容在统计窗口内缺失的指标日期，并看到缺失原因和补录提示。缺失提醒必须基于指标模板的 `required`、发布完成时间、统计窗口、目标平台匹配关系和模板启用状态计算；只针对已发布、目标有效、模板启用且必填的指标生成，不对未发布内容、非必填指标、非目标平台指标或无效目标制造误报。

- **FR-012（P1）从缺失提醒进入补录流程**  
  用户可以从缺失数据提醒直接进入指标补录入口，减少重复筛选和重复填写。若补录入口需要的上下文缺失，页面应提示具体缺失项，而不是静默失败。

### 前端页面与交互闭环

- **FR-013（P0）实现指标相关页面**  
  前端必须实现项目工作区 / 指标表现、指标录入、趋势图、缺失数据提醒四类页面，并覆盖对应的主要列表、表单、筛选、详情跳转和提交流程。

- **FR-014（P0）页面基于原型实现可点击交互**  
  页面必须基于仓库实际原型文件 `docs/requirements/ai-content-factory-clickable-prototype.html` 中对应原型实现；该文件对应原始需求中的 `prototype/ai-content-factory-clickable-prototype.html` 原型定位。不允许只提供空路由或裸 HTML。按钮、筛选、分页、跳转、表单校验、提交、重试、弹窗和反馈提示都必须可点击且有结果反馈。

- **FR-015（P0）页面绑定真实接口与统一反馈**  
  页面数据加载、表单提交、汇总查询、趋势查询和缺失提醒必须绑定本迭代定义的接口契约。成功时显示明确成功反馈；失败时展示统一错误结构中的错误码、错误信息和 request_id。

- **FR-016（P0）页面-接口映射覆盖交付清单**  
  指标页面的列表加载、模板选择、单条录入、批量导入、记录筛选、汇总查询、趋势查询和缺失提醒必须覆盖本迭代需求文档定义的接口清单。页面不得调用未定义接口完成核心流程；如原型字段与接口契约存在差异，以本迭代接口契约为准并保留偏差说明。

## 3. Non-Functional Requirements

- **可追溯性**：指标记录必须稳定关联项目、内容单元、内容版本、发布任务、发布目标、平台、外部链接、来源类型和来源引用，确保后续可以回溯数据来源。
- **一致性**：重复录入、批量导入和修正操作不得制造多条冲突记录；数据结果、幂等行为和操作日志必须一致。
- **可审计性**：指标录入、修正和关键状态变更必须留下操作日志，能够追踪操作者、时间、原因和前后变化。
- **接口契约一致性**：相关接口必须遵守 `/api/v1`、统一成功/失败响应结构、分页结构、错误码约定和 Bearer token 鉴权约束。
- **前端可用性**：四个核心页面都必须具备空态、加载态、错误态和成功反馈；刷新后可直接访问，不出现 404 或导航丢失。
- **蓝图边界**：Core 层保持内容类型无关；本迭代只完成人工录入和可追踪导入闭环，不把自动采集、插件同步或策略建议生成塞入本次范围。
- **策略输入可复现性**：指标汇总和趋势结果必须来自可复现的聚合口径或稳定快照，不得只依赖前端临时计算结果作为后续策略输入。

## 4. 验收标准

- **AC-001（对应 FR-001/FR-002）**：用户可以创建并查看指标模板；缺少必填字段、口径不合法或指标编码重复时，页面展示明确错误。
- **AC-002（对应 FR-003）**：用户可以为已发布内容录入单条指标，并看到返回的指标记录标识和标准化值；录入记录包含发布关联、外部链接、来源类型和来源引用；模板不存在、模板未启用、值类型不匹配或关联对象无效时提交失败。
- **AC-003（对应 FR-004）**：用户可以批量导入多条指标记录，并获得成功数量、失败数量和逐条错误原因；单条失败不会遮蔽其他结果。
- **AC-004（对应 FR-005）**：同一唯一粒度下重复提交不会生成多条冲突记录；重复相同请求返回一致结果，冲突值提交返回冲突错误。
- **AC-005（对应 FR-006/FR-007）**：用户可以筛选、分页查看指标录入记录；如果本迭代提供修正能力，则必须能追踪修正前后值、修正原因和操作者，且修正目标不存在或理由缺失时操作失败。
- **AC-006（对应 FR-008）**：用户可在“指标表现”页面按时间范围、平台、目标和指标编码查看汇总结果，并看到聚合口径、来源记录数量和稳定汇总快照标识或等价可复现结果引用；无数据与失败场景有清晰区分。
- **AC-007（对应 FR-009）**：用户可从项目工作区导航进入四个核心页面，刷新页面后仍可访问，并有当前位置提示或导航高亮。
- **AC-008（对应 FR-010）**：用户可以查看按日、周或月分桶的趋势序列，并看到缺失点标记；缺失数据不会被直接显示为 0。
- **AC-009（对应 FR-011/FR-012）**：用户可以查看缺失日期、缺失原因和补录提示，并能从缺失提醒进入补录流程；缺失提醒只针对已发布、目标有效、模板启用且必填的指标生成，未发布内容、非必填指标、非目标平台指标不会生成缺失提醒。
- **AC-010（对应 FR-013/FR-014）**：指标表现、指标录入、趋势图、缺失数据提醒页面均具备管理台样式和可点击交互，不出现裸 HTML。
- **AC-011（对应 FR-015/FR-016）**：页面成功时有明确反馈；失败时展示错误码、错误信息和 request_id；主要流程可切换真实接口完成联调，并覆盖本迭代接口清单中的模板、录入、批量导入、记录列表、汇总、趋势和缺失提醒接口。

## 5. Out of Scope

- 不做策略建议生成、确认、忽略或执行，这些属于后续 Iteration 9 范围。
- 不做自动平台采集、浏览器插件抓取、外部平台 API 同步或回调接入闭环，这些属于后续 Adapter / Extension 能力。
- 不做独立的指标修正管理页；如本迭代通过接口或录入流程支持修正，必须满足审计要求。
- 不做与指标无关的新项目管理、内容编辑、发布流程改造或审核流程改造。
- 不做脱离项目工作区的独立大盘级策略系统。
- 不把缺失数据自动补 0，不在前端临时计算后直接作为策略输入。

## 6. 依赖说明

- 依赖 Iteration 1 的项目与内容类型边界，所有指标能力均基于 `project_id` 和内容类型上下文工作。
- 依赖 Iteration 4 的 `ContentItem`，用于关联具体内容单元表现。
- 依赖 Iteration 5 的 `content_version`，用于稳定归因到发布版本。
- 依赖 Iteration 7 的 `PublishJob`、`PublishTarget`、`external_url` 和发布时间信息，作为指标录入和缺失提醒的前置条件。
- 本迭代的输出将为后续 Iteration 9 的策略建议提供稳定输入，但本次不直接产出策略动作。
