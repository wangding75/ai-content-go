# Iteration 0 PRD：项目脚手架与基础工程

## 1. 功能概述

本次迭代建立 AI Content Factory 的基础工程底座，覆盖 Go API Server、Next.js 管理台壳层、基础健康与系统检查入口、OpenAPI 文档入口、数据库迁移基线、结构化日志与 CI 基线。

本迭代目标是让后续业务迭代可以在统一工程结构、统一 API 契约、统一页面反馈与统一运行检查能力之上继续开发；不交付具体内容生产、Workflow、Agent、发布、指标或策略业务闭环。

## 2. Functional Requirements

### FR-001：Go API Server 工程底座（P0）

- 功能点描述：系统必须提供可启动的 Go API Server 工程，作为后续 REST API 的统一入口。
- 输入：开发者启动服务；客户端访问系统基础接口。
- 输出：服务可正常启动，并对外暴露 `/api/v1` 下的基础接口。
- 异常处理：服务启动失败时，应通过结构化日志输出失败原因；接口异常时必须返回统一错误响应结构和 `request_id`。

### FR-002：统一 API 响应契约（P0）

- 功能点描述：所有本迭代接口必须遵守统一响应结构，包含 `success`、`data`、`error`、`request_id`。
- 输入：客户端调用任一本迭代接口，可携带 `X-Request-Id`。
- 输出：成功响应返回 `success=true`、业务数据和 `request_id`；失败响应返回 `success=false`、统一错误对象和 `request_id`。
- 异常处理：请求处理失败时，必须返回明确错误码、错误信息和 `request_id`，不得以 HTTP 200 表示业务错误。

### FR-003：健康检查接口（P0）

- 功能点描述：系统必须提供服务健康检查能力，用于默认页展示服务状态，也用于部署和运维探测。
- 输入：用户或系统调用 `GET /api/v1/health`。
- 输出：返回服务状态、服务名、版本号和当前时间戳。
- 异常处理：服务不可用时应返回非 2xx 状态，并使用统一错误响应结构。

### FR-004：系统信息接口（P0）

- 功能点描述：系统必须提供基础系统信息查询能力，用于页面展示应用名称、运行环境和构建信息。
- 输入：用户访问系统默认页或调用 `GET /api/v1/system/info`。
- 输出：返回 `app_name`、`environment`、`build_commit` 等系统信息。
- 异常处理：信息缺失时应返回可识别的占位或空值，不应导致页面整体不可用。

### FR-005：系统配置检查接口（P0）

- 功能点描述：系统必须提供配置项存在性检查能力，帮助用户确认必要运行配置是否已设置。
- 输入：用户访问配置检查页或调用 `GET /api/v1/system/config-check`。
- 输出：返回配置项检查结果，能区分已配置、缺失或不可用状态。
- 异常处理：配置缺失时接口仍应返回成功响应，并在数据中标明缺失项；检查过程异常时返回统一错误响应。

### FR-006：数据库连接检查接口（P0）

- 功能点描述：系统必须提供 PostgreSQL 连接检查能力，用于健康检查页展示数据库连通性和延迟。
- 输入：用户访问健康检查页或调用 `GET /api/v1/system/db-check`。
- 输出：返回数据库状态和 `latency_ms`。
- 异常处理：数据库不可连接时必须返回统一错误响应，页面需要展示错误码、错误信息和 `request_id`。

### FR-007：迁移状态检查接口（P0）

- 功能点描述：系统必须提供数据库迁移状态检查能力，用于运维确认已应用迁移和待应用迁移。
- 输入：用户访问运维检查区域或调用 `GET /api/v1/system/migration-status`。
- 输出：返回 `applied_migrations` 和 `pending_migrations`。
- 异常处理：迁移状态无法读取时返回统一错误响应；没有待应用迁移时应返回空列表而非错误。

### FR-008：OpenAPI 文档入口（P0）

- 功能点描述：系统必须提供 OpenAPI 输出占位和前端文档入口，使用户能从管理台进入 API 文档页面。
- 输入：用户访问 Swagger / OpenAPI 入口页。
- 输出：页面展示 OpenAPI 入口，并能引导用户查看本迭代接口契约。
- 异常处理：OpenAPI 文档暂不可用时，页面必须显示明确错误态或占位说明。

### FR-009：Next.js 管理台壳层（P0）

- 功能点描述：系统必须提供基础 Web Admin 壳层，包含默认页 / 健康检查页、Swagger / OpenAPI 入口页、系统配置检查页。
- 输入：用户在浏览器访问管理台页面，点击检查、刷新、打开文档等主要按钮。
- 输出：页面能够展示加载态、空状态、错误态、成功反馈，并将主要操作映射到明确 API。
- 异常处理：API 调用失败时页面必须展示错误码、错误信息和 `request_id`；主要按钮必须有可点击反馈。

### FR-010：操作日志基线（P1）

- 功能点描述：系统必须建立 `operation_log` 能力基线，用于后续状态变更记录。
- 输入：未来状态变更类操作发生时写入日志；本迭代至少需要具备迁移和工程结构支撑。
- 输出：系统具备记录操作类型、操作对象、操作者、原因或备注、发生时间的基础能力。
- 异常处理：写入操作日志失败时，状态变更类操作在后续迭代不得静默成功。

### FR-011：异步任务基线（P1）

- 功能点描述：系统必须建立异步任务执行基线，为后续不阻塞 HTTP 请求的 worker / queue 能力做准备。
- 输入：后续异步动作触发请求。
- 输出：异步动作应立即返回 `run_id` 或 `job_id`；本迭代至少需要提供工程结构或占位能力。
- 异常处理：任务无法入队时必须返回统一错误响应，不得同步阻塞等待最终执行结果。

### FR-012：CI 基线（P0）

- 功能点描述：系统必须提供基础 CI 检查，使后续迭代能持续验证构建和测试。
- 输入：代码提交或 CI 触发。
- 输出：执行 Go 构建、Go 测试，以及前端基础检查。
- 异常处理：任一检查失败时 CI 应失败，并输出可定位的错误信息。

### FR-013：内容类型无关命名约束（P0）

- 功能点描述：Core 层和基础接口不得以 Novel / Book / Chapter 作为核心资源命名。
- 输入：本迭代新增的工程目录、接口、DTO、页面文案和数据库基础对象。
- 输出：核心命名保持 ContentProject、ContentType、ContentItem 等通用模型方向。
- 异常处理：如页面原型中出现后续内容包示例，必须仅作为后续迭代占位，不进入 Core 基础资源命名。

## 3. Non-Functional Requirements

### NFR-001：API 契约一致性（P0）

本迭代所有接口必须位于 `/api/v1` 前缀下，并遵守统一成功、失败和分页响应约定。

### NFR-002：可观测性（P0）

服务必须使用结构化日志记录请求处理、启动失败、依赖检查失败等关键事件，并包含可关联请求的 `request_id`。

### NFR-003：安全基线（P0）

API 契约要求 Bearer Token 认证；本迭代允许开发早期占位，但不得在代码、日志或页面中暴露真实凭证。

### NFR-004：数据库与迁移基线（P0）

系统必须以 PostgreSQL 为数据库目标，并使用 goose 或等价迁移工具管理迁移。

### NFR-005：前端可用性（P0）

本迭代页面必须支持加载态、空状态、错误态和成功反馈，失败反馈必须包含错误码、错误信息和 `request_id`。

### NFR-006：工程可演进性（P1）

工程结构必须能支撑后续 content、workflow、agent、llm、memory、publish、metrics、strategy 等模块扩展，但本迭代不得实现超出脚手架范围的业务功能。

## 4. 验收标准

- AC-001：启动 Go API Server 后，`GET /api/v1/health` 返回统一成功响应，并包含服务状态、服务名、版本号和时间戳。
- AC-002：`GET /api/v1/system/info` 返回统一成功响应，并包含应用名称、运行环境和构建提交信息。
- AC-003：`GET /api/v1/system/config-check` 能展示配置项检查结果；缺失配置以数据状态呈现，不导致页面崩溃。
- AC-004：`GET /api/v1/system/db-check` 能返回数据库状态和延迟；数据库不可用时返回统一错误响应。
- AC-005：`GET /api/v1/system/migration-status` 能返回已应用迁移和待应用迁移列表。
- AC-006：所有本迭代接口的成功和失败响应均包含 `success`、`data`、`error`、`request_id`。
- AC-007：OpenAPI 文档入口页面可访问，并能展示或跳转到本迭代接口契约。
- AC-008：默认页 / 健康检查页能展示服务状态，并能触发健康或系统检查相关操作。
- AC-009：系统配置检查页能展示配置检查结果，并支持加载、成功、错误反馈。
- AC-010：Swagger / OpenAPI 入口页具备可点击反馈；文档暂不可用时显示明确占位或错误态。
- AC-011：主要页面按钮均有可点击反馈，不出现无响应的主路径按钮。
- AC-012：页面 API 调用失败时展示错误码、错误信息和 `request_id`。
- AC-013：数据库迁移中存在 `operation_log` 基线能力。
- AC-014：工程结构包含或预留异步 worker / queue 基线，后续异步接口可以返回 `run_id` 或 `job_id`。
- AC-015：CI 能执行基础构建和测试检查，失败时阻断通过。
- AC-016：Core 层新增命名不使用 Novel / Book / Chapter 作为基础资源名。

## 5. Out of Scope

- 不实现项目管理、内容类型管理、Prompt 管理、LLM Provider 管理等 Iteration 1 业务能力。
- 不实现 Workflow Engine、Agent Runtime、LLMCallLog 的完整业务闭环。
- 不实现内容生成、审稿、发布、指标、策略建议或 Portfolio 业务功能。
- 不实现 n8n 核心编排；n8n 仅作为后续外围自动化方向。
- 不实现 Browser Extension。
- 不引入 Novel / Book / Chapter 作为 Core 层基础资源命名。
- 不修改 `docs/requirements/` 下的原始需求文档。

## 6. 依赖说明

- PostgreSQL：用于数据库连接检查、迁移状态检查和后续业务数据持久化。
- goose 或等价迁移工具：用于管理数据库迁移。
- OpenAPI 3.0 工具链：用于输出接口文档。
- Next.js + TypeScript：用于管理台壳层。
