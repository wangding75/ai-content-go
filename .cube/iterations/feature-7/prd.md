# Iteration 7 PRD：发布队列与手动发布回填

## 1. 功能概述

本次迭代建立项目工作区内的发布队列与手动发布闭环。用户可以为已审稿通过、可发布的内容版本创建发布任务，按发布目标查看和筛选队列，打开发布详情，复制可追溯的发布载荷，并在人工完成平台发布后回填发布结果；发布失败时可记录原因并按允许状态重新入队。

本迭代同时提供发布目标管理能力，支撑按项目维护平台账号、栏目或发布位置等非敏感展示配置。所有发布状态变更和关键行为必须可追踪，并为后续指标录入保留稳定关联信息。

## 2. Functional Requirements

### 发布目标管理

- **FR-001（P0）在创建发布任务中维护发布目标**  
  用户可以在“创建发布任务”弹窗或内嵌表单中选择、新建、编辑项目级发布目标，输入平台、账号名称、展示名称和非敏感展示配置。本迭代不做独立发布目标管理页。创建成功后返回发布目标 ID 并可立即用于发布任务。输入缺少必填字段或 config 包含 token、cookie、密码、API key、密钥引用等敏感字段时，系统返回统一错误结构并展示错误码、错误信息和 request_id。

- **FR-002（P0）查看发布目标列表**  
  用户可以在创建发布任务流程中按项目查看可用发布目标列表，列表输出目标平台、账号名称、展示名称、启用状态和展示配置摘要。项目没有发布目标时，创建任务表单展示空状态并引导在当前弹窗或内嵌表单中新建发布目标；接口失败时页面展示统一错误信息。

### 发布任务创建与队列查看

- **FR-003（P0）基于可发布内容创建发布任务**  
  用户可以选择已审稿通过、可发布的 ContentItem / content_version 和目标发布目标创建发布任务。创建成功后返回 publish_job_id 和初始状态 queued。未通过审稿、生成失败、已归档或缺少内容版本的内容不得进入发布队列，系统返回校验错误或状态冲突错误。

- **FR-004（P0）查看发布队列列表**  
  用户可以在项目工作区的“发布队列”页面查看发布任务分页列表，列表支持按 project_id、target_id、status、scheduled_at 筛选，并支持分页、排序和排序方向。列表输出内容摘要、目标平台、状态、计划时间、复制时间、发布时间、最近错误和可执行操作。无数据时展示空状态；加载中展示加载态；请求失败时展示错误码、错误信息和 request_id。

- **FR-005（P0）从导航进入发布队列**  
  用户必须能从项目详情 / 项目工作区菜单进入发布队列页面，页面刷新后仍可直接访问并显示当前位置或导航高亮。不允许核心页面只能通过手输 URL 访问。

### 发布详情与日志查看

- **FR-006（P0）查看发布任务详情**  
  用户可以打开发布任务详情页，查看发布任务状态、目标平台、关联内容版本、外部链接、发布时间、最近错误、重试次数和日志摘要。详情页必须调用详情接口获取最新数据，不依赖列表缓存。任务不存在时返回 NOT_FOUND 并显示统一错误态。

- **FR-007（P1）查看发布行为摘要**  
  用户可以在详情页看到复制、标记已发布、标记失败、重新入队等关键行为的时间、操作者、原因或备注摘要。日志为空时展示“暂无发布日志”。

### 复制发布内容

- **FR-008（P0）打开复制发布内容页面**  
  用户可以从发布队列或发布详情进入复制发布内容页面，查看标题、正文、格式、平台、目标 ID、内容版本 ID 和 payload_hash。复制载荷必须绑定 content_version_id，避免内容后续编辑导致发布不可追溯。任务不存在或状态不允许复制时，系统返回统一错误。

- **FR-009（P0）点击复制按钮并记录行为**  
  用户点击复制标题、正文或完整载荷按钮时，页面必须调用 `POST /api/v1/publish-jobs/:id/copy`，给出成功反馈，并记录发布复制行为，包含操作者、时间、载荷版本与目标平台。只有点击复制按钮才写 publish_log 并将 queued 状态任务变更为 copied；打开复制页或请求 `GET /api/v1/publish-jobs/:id/copy-payload` 只做预览，不写日志、不改变状态。重复点击复制按钮应遵守幂等或状态机约束，不得产生不可解释的重复日志或状态反复跳变。

- **FR-010（P1）平台格式轻量适配**  
  如果发布目标需要轻量格式转换，复制载荷应按本迭代已定义规则返回适合平台的 format 和内容展示。复杂平台适配、自动填充和浏览器插件协作不在本迭代完成。

### 手动发布回填

- **FR-011（P0）标记已发布**  
  用户完成外部平台人工发布后，可以回填 external_url、published_at 和备注，将 copied 状态任务标记为 published。允许 external_url 为空；但 external_url 为空时必须填写 note 或 reason，说明平台不提供 URL 或无法获取链接。external_url 非空但格式不合法、任务不是 copied 状态或任务已处于终态时，系统返回校验错误或状态冲突错误。

- **FR-012（P0）标记发布失败**  
  用户可以将 queued 或 copied 状态任务标记为 failed，必须输入失败原因，并可说明是否可重试和备注。系统记录失败原因、可重试性和最近失败时间。缺少失败原因或状态不允许失败回填时，系统返回统一错误。

- **FR-013（P0）重新入队**  
  用户可以将 failed、copied 或明确允许重试的任务重新入队，输入重新入队原因和可选 scheduled_at。重新入队成功后状态变为 queued，retry_count 增加并保留历史失败原因。published 终态任务不得重新入队。

- **FR-014（P0）回填与复制动作幂等**  
  创建发布任务、点击复制、标记已发布、标记失败和重新入队必须支持 Idempotency-Key。相同幂等键下重复提交同一请求应返回相同结果，不得重复追加日志或导致状态反复跳变；相同幂等键但请求体不一致时返回 IDEMPOTENCY_CONFLICT。

### 状态机与审计

- **FR-015（P0）执行发布状态机约束**  
  系统必须按 queued、copied、published、failed、canceled 等状态约束允许动作：queued 可点击复制或标记失败；copied 可标记已发布或失败；failed 可重新入队；published 为终态，不允许失败或重新入队。canceled 仅作为后续状态枚举预留，本迭代不开放取消发布，不提供取消按钮，不提供取消接口。非法流转返回 CONFLICT。

- **FR-016（P0）记录发布日志和操作日志**  
  所有状态变更必须同时写入 operation_log 和 publish_log；复制行为至少写入 publish_log。日志需包含事件类型、来源状态、目标状态、操作者、原因、备注、载荷快照或摘要、创建时间。日志写入失败时，对应状态变更不得被视为成功。

### 前端页面与交互

- **FR-017（P0）实现发布队列相关页面**  
  前端必须实现项目工作区 / 发布队列、发布详情、复制发布内容和发布回填页面。页面路由分别覆盖 `/projects/:projectId/publish-jobs`、`/publish-jobs/:jobId`、`/publish-jobs/:jobId/copy`、`/publish-jobs/:jobId/backfill` 或等价可访问路由。

- **FR-018（P0）页面基于原型渲染并具备真实交互**  
  页面必须参考 `docs/requirements/ai-content-factory-clickable-prototype.html` 中项目工作区的发布队列原型，具备管理台视觉样式、统一 AppLayout、卡片 / 表格 / 表单 / 弹窗 / 状态标签和可执行 JS 交互。筛选、分页、详情跳转、复制、表单提交、状态操作、Toast 或 Alert 反馈必须可点击且有结果反馈。

- **FR-019（P0）绑定真实 API 契约**  
  页面列表、详情、复制载荷、创建任务、标记已发布、标记失败、重新入队和发布目标列表必须绑定本迭代 API。允许开发期 mock，但验收必须能切换真实 API；失败态必须展示统一错误结构中的 error.code、error.message 和 request_id。

## 3. Non-Functional Requirements

- **安全性**：发布目标 config 只允许保存非敏感展示配置，不保存 token、cookie、密码、API key、密钥引用或任何凭证字段；接口必须遵守 Bearer token 认证约束。
- **可追溯性**：复制载荷必须绑定 content_version_id 和 payload_hash；状态变更、复制行为和回填行为必须可通过日志追踪。
- **一致性**：发布任务状态变更和日志写入必须保持一致；幂等请求不得造成重复日志或重复状态跳转。
- **API 契约一致性**：所有接口必须使用 `/api/v1`、统一响应结构、统一错误结构、Go DTO、validator 校验、分页结构和 OpenAPI 描述。
- **前端可用性**：页面必须支持空态、加载态、错误态和成功反馈；刷新后不应 404；核心页面必须有导航入口和当前位置提示。
- **蓝图边界**：Core 层不得引入 Novel / Book / Chapter 等核心资源命名；本迭代不得使用 n8n 承载发布状态机或核心回填逻辑。

## 4. 验收标准

- **AC-001（对应 FR-001/FR-002）**：用户可在创建发布任务弹窗或内嵌表单中选择、新建、编辑项目级发布目标，并在列表中看到目标；缺少必填字段或包含敏感配置时页面展示统一错误信息。
- **AC-002（对应 FR-003）**：用户只能基于已审稿通过的内容版本创建发布任务；不可发布内容创建失败并返回明确错误。
- **AC-003（对应 FR-004/FR-005）**：用户可从项目工作区导航进入发布队列，按状态和目标筛选，分页切换，刷新页面后仍可访问并保持当前位置提示。
- **AC-004（对应 FR-006/FR-007）**：用户从列表进入详情页后，详情页展示任务、目标、内容版本和日志摘要；任务不存在时展示 NOT_FOUND 和 request_id。
- **AC-005（对应 FR-008/FR-009）**：用户打开复制页面能看到 title、body、format、platform、target_id、content_version_id、payload_hash，且任务状态不因打开页面或请求预览接口改变；点击复制按钮后页面调用 `POST /api/v1/publish-jobs/:id/copy` 并显示成功反馈，同时能观察到任务进入 copied 或记录复制日志。
- **AC-006（对应 FR-011）**：copied 状态任务可回填 published_at 和备注后进入 published；external_url 可为空，但为空时必须填写 note 或 reason；external_url 非空但格式非法或状态不允许时返回错误且状态不变。
- **AC-007（对应 FR-012）**：queued 或 copied 状态任务可标记 failed，必须记录失败原因、可重试性和最近失败时间；缺少 reason 时提交失败。
- **AC-008（对应 FR-013）**：failed 或允许重试状态任务可重新入队，retry_count 增加；published 任务重新入队返回 CONFLICT。
- **AC-009（对应 FR-014）**：相同 Idempotency-Key 重复提交相同回填请求返回相同结果且不重复追加日志；相同键不同请求体返回 IDEMPOTENCY_CONFLICT。
- **AC-010（对应 FR-015/FR-016）**：所有状态变更符合状态机约束，并能在 operation_log 和 publish_log 中看到对应记录；非法流转返回 CONFLICT。
- **AC-011（对应 FR-017/FR-018）**：发布队列、发布详情、复制发布内容、发布回填页面均有管理台样式，不出现裸 HTML，主要按钮、筛选、跳转、弹窗和提交交互均可点击并有反馈。
- **AC-012（对应 FR-019）**：前端错误态展示 error.code、error.message 和 request_id；e2e 或集成测试覆盖导航进入页面、接口成功渲染、主要操作和接口失败渲染。
- **AC-013（对应 NFR）**：OpenAPI 包含本迭代所有接口的 summary、description、tags、operationId、parameters、requestBody、responses、security 和 examples。
- **AC-014（对应 NFR）**：发布完成后的记录保留 project_id、content_item_id、target_id、external_url 和 published_at，可供下一迭代指标录入关联。

## 5. Out of Scope

- 不做独立发布目标管理页；发布目标只在创建发布任务流程中选择、新建、编辑。
- 不做平台自动发布、自动登录、自动点击提交或自动抓取平台发布结果。
- 不做取消发布按钮或取消发布接口；canceled 仅作为后续状态枚举预留。
- 不做 Browser Extension 自动填充、插件拉取任务或插件回填；这些能力留给 Iteration 11。
- 不做复杂平台格式转换、平台 API 对接或平台凭证管理；不保存 token、cookie、密码、API key、密钥引用或任何凭证字段。
- 不做 n8n 核心编排、发布状态机或回填逻辑。
- 不做内容正文编辑；如需修改正文，应回到审稿 / 内容版本流程。
- 不做超出发布队列、发布详情、复制发布内容、发布回填和发布目标支撑之外的业务页面。
- 不引入 Novel / Book / Chapter 作为 Core 层发布资源命名。

## 6. 依赖说明

- 依赖 Iteration 1 的 ContentProject / ContentType，发布目标和发布任务均以 project_id 作为边界。
- 依赖 Iteration 4 的 ContentItem，发布任务关联已生成的内容单元。
- 依赖 Iteration 5 的 content_review / content_version，只有已审核通过的内容版本可进入发布队列。
- 与 Iteration 6 的 Knowledge Memory 无直接改造关系，发布结果可作为后续动态状态或项目事件来源。
- 为 Iteration 8 的 MetricRecord 提供 external_url、published_at 和目标平台信息。
- 与 Iteration 11 的 Platform Adapter / Browser Extension 保持边界：本迭代只完成手动发布闭环。
