# Iteration 5 PRD：审稿与质量控制

## 1. 功能概述

本次迭代建立通用内容审核与质量控制流程，覆盖后端审稿记录、内容版本、质检报告能力，以及前端项目工作区中的审稿中心、审稿详情、AI 质检报告和编辑后通过页面。

用户可以在项目工作区查看待审稿内容、按条件筛选审稿任务、为内容单元创建审稿、查看正文与审稿报告、查看版本历史、触发 AI 质检生成、通过审稿、仅打回或打回并触发重生成，或按内容类型编辑字段后通过审稿。所有页面必须接入明确 API，并具备空态、加载态、错误态、成功反馈和可点击导航入口。

## 2. Functional Requirements

### 2.1 审稿中心列表与筛选

- **FR-001（P0）**：用户可以从项目工作区导航进入审稿中心。
  - 输入：项目 ID。
  - 输出：审稿中心页面，展示当前项目的待审稿列表入口、筛选区和创建审稿入口。
  - 异常处理：项目不存在或无权限时，页面展示统一错误码、错误信息和 `request_id`。

- **FR-002（P0）**：用户可以查看内容审稿列表。
  - 输入：`project_id`、审稿状态、分页参数、排序参数。
  - 输出：分页审稿列表，包含审稿记录、关联内容单元、当前状态、更新时间和可执行操作。
  - 异常处理：无数据时展示空态；接口失败时展示错误码、错误信息和 `request_id`；分页参数不合法时返回校验错误。

- **FR-003（P0）**：用户可以按状态筛选审稿列表。
  - 输入：审稿状态、分页参数。
  - 输出：符合筛选条件的审稿列表，并保留当前筛选条件。
  - 异常处理：状态值不合法时展示参数错误；筛选结果为空时展示空态而不是报错。

### 2.2 创建审稿

- **FR-004（P0）**：用户可以为指定内容单元创建审稿记录。
  - 输入：内容单元 ID、审稿类型。
  - 输出：新建的审稿记录 ID，并刷新或跳转到相关审稿信息。
  - 异常处理：内容单元不存在、状态不允许创建审稿、重复创建冲突或审稿类型不合法时，返回统一错误结构并在页面展示。

### 2.3 审稿详情

- **FR-005（P0）**：用户可以打开审稿详情查看正文、审稿报告和版本历史入口。
  - 输入：审稿记录 ID。
  - 输出：审稿详情，包括正文内容、审稿状态、审稿报告摘要、版本信息和可执行操作。
  - 异常处理：审稿记录不存在或无权限时展示统一错误；详情加载中显示加载态。

- **FR-006（P1）**：用户可以查看指定内容单元的版本历史。
  - 输入：内容单元 ID。
  - 输出：内容版本列表，包含版本 ID、版本号、创建时间、变更来源和可读摘要。
  - 异常处理：无历史版本时展示空态；内容单元不存在时展示统一错误。

### 2.4 AI 质检报告

- **FR-007（P0）**：用户可以查看 AI 质检报告。
  - 输入：审稿记录 ID。
  - 输出：质检报告、问题项、风险等级、建议处理方式和报告状态。
  - 异常处理：报告不存在时展示空态或待生成状态；报告生成失败时展示错误码、错误信息和 `request_id`。

- **FR-020（P0）**：用户可以触发 AI 质检报告生成。
  - 输入：审稿记录 ID、质检类型或默认质检配置。
  - 输出：异步质检任务 ID 或运行记录 ID，并在页面展示生成中状态和结果查看入口。
  - 异常处理：审稿记录不存在、状态不允许质检、重复触发冲突或任务创建失败时展示统一错误；HTTP 请求不得同步等待最终报告生成。

### 2.5 状态变更：通过、打回、编辑后通过

- **FR-008（P0）**：用户可以通过审稿。
  - 输入：审稿记录 ID、通过备注。
  - 输出：审稿状态变更结果和操作日志 ID。
  - 异常处理：状态不允许通过、审稿记录不存在、备注不合法或无权限时返回统一错误；页面保留用户已输入内容。

- **FR-009（P0）**：用户可以打回审稿，并选择是否触发重生成。
  - 输入：审稿记录 ID、打回原因、重生成说明、是否触发重生成。
  - 输出：仅打回时返回审稿状态变更结果；打回并重生成时同时返回异步重生成任务 ID 或运行记录 ID。
  - 异常处理：缺少打回原因、状态不允许打回、记录不存在、重生成任务创建失败时展示统一错误；任务创建失败不得造成用户误以为已成功触发重生成。

- **FR-010（P0）**：用户可以按内容类型编辑字段后通过审稿。
  - 输入：审稿记录 ID、由 Content Pack 定义的可编辑字段、通过备注。
  - 输出：新的内容版本 ID，以及审稿通过状态。
  - 异常处理：必填字段为空、字段超出内容类型限制、状态不允许编辑后通过或版本保存失败时展示统一错误；页面不得丢失用户已编辑内容。

### 2.6 操作日志与状态反馈

- **FR-011（P0）**：所有审稿状态变更必须记录操作日志。
  - 输入：状态变更动作、操作者、目标审稿记录、备注或原因。
  - 输出：操作日志 ID 或可追踪的状态变更结果。
  - 异常处理：操作日志写入失败时状态变更不得静默成功，用户看到明确失败反馈。

- **FR-012（P0）**：前端必须展示完整状态反馈。
  - 输入：列表、详情、表单提交和状态操作的接口响应。
  - 输出：空态、加载态、成功 Toast 或 Alert、失败错误展示。
  - 异常处理：失败态必须展示统一错误结构中的 `error.code`、`error.message` 和 `request_id`。

### 2.7 前端页面与导航

- **FR-013（P0）**：必须实现项目工作区 / 审稿中心页面。
  - 输入：项目 ID、筛选与分页条件。
  - 输出：符合原型布局的审稿列表、筛选、创建审稿和详情跳转能力。
  - 异常处理：刷新页面后仍可访问；页面不可用时展示样式化错误态。

- **FR-014（P0）**：必须实现审稿详情页面。
  - 输入：审稿记录 ID。
  - 输出：正文、审稿报告摘要、版本历史入口和状态操作按钮。
  - 异常处理：详情缺失或接口失败时展示统一错误态。

- **FR-015（P0）**：必须实现 AI 质检报告页面。
  - 输入：审稿记录 ID。
  - 输出：AI 质检报告和问题项列表。
  - 异常处理：报告为空、加载失败或生成失败时提供明确反馈。

- **FR-016（P0）**：必须实现编辑后通过页面。
  - 输入：审稿记录 ID、由内容类型决定的可编辑字段、通过备注。
  - 输出：按 Content Pack 渲染的编辑表单、保存并通过结果、成功反馈和跳转入口。
  - 异常处理：校验失败或提交失败时展示错误并保留编辑内容。

- **FR-017（P0）**：本迭代新增页面必须接入现有导航体系。
  - 输入：项目详情或项目工作区菜单点击。
  - 输出：可进入审稿中心，并在当前路由显示导航高亮或当前位置提示。
  - 异常处理：不允许核心页面只能通过手输 URL 访问；刷新后不得 404。

### 2.8 API 契约与页面映射

- **FR-018（P0）**：后端必须提供审稿相关 API，并保持统一响应结构。
  - 输入：列表、创建、详情、通过、打回、编辑后通过、版本历史相关请求。
  - 输出：符合 `/api/v1`、统一成功响应、统一错误响应和分页响应的 JSON。
  - 异常处理：参数错误、未授权、无权限、资源不存在、状态冲突和内部错误均使用统一错误码与 `request_id`。

- **FR-019（P0）**：前端页面动作必须绑定对应 API。
  - 输入：页面加载、筛选、创建、查看详情、触发 AI 质检、通过、仅打回、打回并重生成、编辑后通过、查看版本历史等用户动作。
  - 输出：调用明确 API，并根据成功或失败响应刷新页面或展示反馈。
  - 异常处理：不允许用不可追踪 mock 替代验收联调；接口失败必须在页面上可见。

## 3. Non-Functional Requirements

- **NFR-001（P0，领域边界）**：Core 层资源命名不得使用 Novel / Book / Chapter 作为核心资源名，应使用 ContentProject、ContentItem、ContentReview、ContentVersion、ReviewReport 等通用内容概念。

- **NFR-002（P0，API 契约）**：所有接口必须使用 `/api/v1` REST JSON 风格，返回统一 `success/data/error/request_id` 结构；列表接口必须返回 `items` 和 `pagination`。

- **NFR-003（P0，校验与错误）**：所有请求参数必须校验；失败响应必须包含标准错误码、错误信息、必要的字段级详情和 `request_id`。

- **NFR-004（P0，审计）**：所有审稿状态变更必须写入 `operation_log`，并保证状态变更结果可追踪。

- **NFR-005（P0，前端渲染）**：新增页面必须加载统一管理台样式和 AppLayout，不能出现浏览器默认裸 HTML；按钮、表格、卡片、表单、状态标签必须可见且具备管理台视觉样式。

- **NFR-006（P0，前端交互）**：导航、筛选、分页、弹窗、表单提交、详情跳转、状态操作必须具备可执行 JS 交互和反馈。

- **NFR-007（P0，可访问性与路由）**：核心页面必须可从导航入口进入，刷新后可直接访问，且保留导航高亮或当前位置提示。

- **NFR-008（P0，安全）**：API 必须按统一契约要求支持 Bearer Token 鉴权；不得在 GET 参数或日志中暴露敏感信息。

- **NFR-009（P1，异步与性能）**：如某个质检或状态动作需要异步执行，HTTP 请求不得同步等待最终结果，必须返回可追踪的运行记录 ID、任务 ID 或业务记录 ID。

- **NFR-010（P1，测试）**：需要覆盖从导航进入页面、主要按钮点击、接口成功渲染、接口失败渲染和错误态展示的 e2e 或集成测试。

## 4. 验收标准

- **AC-001（对应 FR-001、FR-017）**：从项目详情或项目工作区菜单可以点击进入 `/projects/:projectId/reviews`，刷新后页面可访问且有当前位置提示。

- **AC-002（对应 FR-002、FR-003）**：审稿中心能展示分页列表；按状态筛选后列表更新；空结果展示空态；接口失败展示 `error.code`、`error.message` 和 `request_id`。

- **AC-003（对应 FR-004）**：用户为内容单元创建审稿后，页面显示成功反馈并能看到新审稿记录或跳转到相关详情；重复或非法创建展示冲突或校验错误。

- **AC-004（对应 FR-005）**：审稿详情页能展示正文、状态、报告摘要、版本历史入口和通过 / 打回 / 编辑后通过操作入口。

- **AC-005（对应 FR-006）**：版本历史接口返回版本列表时，页面能展示版本信息；无版本时展示空态。

- **AC-006（对应 FR-007、FR-020）**：AI 质检报告页能展示问题项、风险等级和建议；报告缺失时可触发异步生成并展示任务 ID 或运行记录 ID；报告失败时页面展示明确状态。

- **AC-007（对应 FR-008、FR-011）**：通过审稿后状态更新，返回或可追踪操作日志 ID；状态不允许通过时返回冲突错误并在页面展示。

- **AC-008（对应 FR-009、FR-011）**：打回审稿时必须填写原因；仅打回时更新状态并记录操作日志；打回并重生成时额外返回异步重生成任务 ID 或运行记录 ID；缺少原因时展示校验错误。

- **AC-009（对应 FR-010）**：编辑后通过会按内容类型可编辑字段创建新的内容版本并更新审稿状态；提交失败时保留编辑内容并展示统一错误。

- **AC-010（对应 FR-012）**：每个新增页面至少覆盖加载态、空态、成功反馈和失败态；失败态展示统一错误结构。

- **AC-011（对应 FR-013 至 FR-016）**：四个前端页面均按原型完成主要布局和交互，不是空白页、占位页或裸 HTML 页面。

- **AC-012（对应 FR-018）**：审稿相关 API 均具备请求 / 响应 DTO、参数校验、统一响应结构、统一错误结构和 OpenAPI 描述。

- **AC-013（对应 FR-019）**：页面加载、筛选、创建、详情、触发 AI 质检、通过、仅打回、打回并重生成、编辑后通过、版本历史均调用明确 API，并能处理成功与失败响应。

- **AC-014（对应 NFR-001）**：Core 层没有新增 Book / Chapter / Novel 作为核心资源命名。

- **AC-015（对应 NFR-010）**：e2e 或集成测试覆盖导航进入审稿中心、主要按钮点击、接口成功渲染和接口失败渲染。

## 5. Out of Scope

- 不实现超出审稿中心、审稿详情、AI 质检报告、编辑后通过页面范围之外的新业务页面。
- 不实现发布队列、指标看板、策略建议或 Knowledge Memory 的完整功能。
- 不使用 n8n 承载核心审稿状态机、Agent 编排或质量控制主流程。
- 不做未定义接口的隐式前端调用。
- 不在 Core 层引入小说专属 Book / Chapter / Novel 命名作为核心资源。
- 不要求本迭代完成真实外部平台发布或数据回填。

## 6. 依赖说明

- 依赖已有项目、内容单元、生成运行和项目工作区导航基础。
- 依赖统一 API 契约：`/api/v1`、统一响应结构、统一错误结构、分页结构、Bearer Token 鉴权和 OpenAPI 描述。
- 依赖前端统一 AppLayout、全局样式和项目工作区导航能力。
- 依赖原型页面 `prototype/ai-content-factory-clickable-prototype.html` 或其等价需求来源作为布局与交互基准。
