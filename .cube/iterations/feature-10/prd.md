# Iteration 10 PRD：Project Portfolio 多项目管理

## 1. 功能概述

本次迭代交付 Project Portfolio 多项目管理能力，为用户提供跨项目组合管理、组合详情查看、组合成员优先级管理、健康与成本汇总观察能力。

Portfolio 是系统级跨项目管理与观察视角，用于按主题、业务线、平台、内容类型或增长目标聚合多个 ContentProject。它不替代项目工作区内的生产、审稿、发布、指标录入和策略执行流程，也不直接触发 WorkflowRun、AgentRuntime 或自动执行策略建议。

本次迭代包含以下功能点：

1. Portfolio 管理：查看、新增、编辑项目组合。
2. Portfolio 详情：查看组合基本信息、项目数量、健康摘要、成本摘要和策略摘要。
3. Portfolio 成员管理：向组合加入项目、查看成员列表、移除项目。
4. 项目优先级管理：调整组合内项目优先级、权重、角色和备注。
5. 健康与成本汇总：查看组合健康状态、风险项、成本汇总、历史快照和来源信息。
6. 前端页面与原型落地：实现 Portfolio 管理、详情、项目优先级、健康 / 成本汇总页面，并接入系统级导航入口。

## 2. Functional Requirements

### Portfolio 管理

#### FR-001：查看 Portfolio 列表（P0）

- 用户可以在系统级导航进入 Portfolio 管理页，查看 Portfolio 列表。
- 输入：分页、状态、范围类型、负责人、排序字段、排序方向等筛选条件。
- 输出：Portfolio 列表、分页信息、每个 Portfolio 的名称、描述、范围类型、负责人、状态、项目数量、健康摘要、成本摘要等可展示信息。
- 异常处理：
  - 无数据时展示空状态和新增入口。
  - 查询失败时展示统一错误码、错误信息和 request_id。
  - 无权限时展示无权限提示，不展示受限 Portfolio 数据。

#### FR-002：新增 Portfolio（P0）

- 用户可以在 Portfolio 管理页创建新的项目组合。
- 输入：名称、描述、范围类型、健康策略等信息。
- 输出：创建成功反馈和新 Portfolio 标识，并刷新列表或跳转详情。
- 异常处理：
  - 必填项缺失或格式不合法时，表单内展示字段级错误。
  - 名称或业务唯一性冲突时展示冲突提示。
  - 重复提交时应避免创建重复组合，并给出明确反馈。

#### FR-003：编辑 Portfolio（P0）

- 用户可以编辑 Portfolio 的名称、描述、状态和健康策略。
- 输入：需要更新的 Portfolio 字段。
- 输出：更新后的 Portfolio 信息和成功反馈。
- 异常处理：
  - Portfolio 不存在时展示资源不存在提示。
  - 用户无权限时展示无权限提示。
  - 状态变更不合法时展示冲突提示。
  - 更新失败时展示统一错误码、错误信息和 request_id。

### Portfolio 详情

#### FR-004：查看 Portfolio 详情（P0）

- 用户可以从列表进入 Portfolio 详情页，查看组合基本信息、项目数量、成员概览、健康摘要、成本摘要和策略摘要。
- 输入：Portfolio 标识。
- 输出：Portfolio 基本信息、成员数量、健康状态、成本摘要、待处理策略建议摘要、最近计算时间和来源时间范围。
- 异常处理：
  - Portfolio 不存在时展示 404 状态。
  - 无权限时展示无权限提示。
  - 摘要数据不足时不得伪造结论，应展示 unknown 状态和缺失原因。

#### FR-005：展示策略建议摘要（P1）

- 用户可以在 Portfolio 详情或健康页面查看跨项目策略建议摘要和待处理数量。
- 输入：策略建议状态、时间范围等筛选条件。
- 输出：策略建议数量、分布、待处理摘要和来源引用。
- 异常处理：
  - 无策略建议时展示空状态。
  - 获取失败时展示统一错误码、错误信息和 request_id。
- 约束：Portfolio 仅展示策略摘要；确认、忽略、执行策略仍回到策略建议功能，不在 Portfolio 中绕过人工确认。

### Portfolio 成员管理

#### FR-006：加入项目到 Portfolio（P0）

- 用户可以在项目优先级页或 Portfolio 详情中将已有 ContentProject 加入 Portfolio。
- 输入：项目标识、优先级、权重、目标角色、备注。
- 输出：成员关系标识和加入成功反馈，并刷新成员列表。
- 异常处理：
  - 项目不存在时展示资源不存在提示。
  - 用户无项目读取权限时展示无权限提示。
  - 项目已归档且不允许观察时展示业务冲突提示。
  - 同一 Portfolio 内重复加入同一项目时展示冲突提示；重复提交同一请求时应返回一致结果或明确提示。

#### FR-007：查看 Portfolio 成员列表（P0）

- 用户可以查看某个 Portfolio 下的项目成员列表。
- 输入：分页、优先级、状态、排序字段、排序方向等筛选条件。
- 输出：成员列表、分页信息、项目名称、项目状态、优先级、权重、角色、备注、健康摘要和成本摘要。
- 异常处理：
  - 无成员时展示空状态和加入项目入口。
  - 成员中的部分项目无权限时，应按权限规则隐藏或提示受限信息。
  - 查询失败时展示统一错误码、错误信息和 request_id。

#### FR-008：从 Portfolio 移除项目（P0）

- 用户可以从 Portfolio 中移除项目成员关系。
- 输入：项目标识、移除原因、备注。
- 输出：移除成功反馈和操作记录标识，并刷新成员列表。
- 异常处理：
  - Portfolio 或项目成员关系不存在时展示资源不存在提示。
  - 无权限时展示无权限提示。
  - 重复移除时应返回明确的冲突或已处理反馈。
- 约束：移除项目只影响 Portfolio 成员关系，不删除 ContentProject，不改变项目状态。

### 项目优先级管理

#### FR-009：调整项目优先级与权重（P0）

- 用户可以调整 Portfolio 内项目的优先级、权重和备注，用于人工资源排序和聚合展示。
- 输入：优先级、权重、备注。
- 输出：更新后的成员状态、成功反馈和操作记录标识。
- 异常处理：
  - 优先级或权重不合法时展示字段级校验错误。
  - 成员关系不存在时展示资源不存在提示。
  - 无权限时展示无权限提示。
- 约束：优先级和权重不得自动暂停项目、改变项目状态或执行策略建议。

#### FR-010：记录成员变更操作日志（P0）

- 用户进行新增成员、移除成员、调整优先级、调整权重等变更时，系统必须留下可追踪的操作记录。
- 输入：变更动作、变更前后值、操作者、原因或备注。
- 输出：操作记录标识，可用于后续审计或详情展示。
- 异常处理：
  - 操作记录写入失败时，变更不得表现为成功。
  - 用户应看到失败原因和 request_id。

### 健康与成本汇总

#### FR-011：查看健康汇总（P0）

- 用户可以查看 Portfolio 的健康状态、健康分数、风险摘要、来源引用和计算时间。
- 输入：时间范围、快照标识。
- 输出：健康状态、健康分数、项目数量、风险项、来源引用、计算时间和数据时间范围。
- 异常处理：
  - 数据不足时展示 unknown 状态，并说明缺失来源。
  - 来源数据查询失败时展示错误态，不伪造健康结论。
  - Portfolio 不存在或无权限时展示对应错误。

#### FR-012：重新计算健康快照（P0）

- 用户可以触发 Portfolio 健康快照重新计算。
- 输入：时间范围、是否强制重算。
- 输出：快照标识或任务标识，并提示用户可通过详情或快照列表查看结果。
- 异常处理：
  - 参数不合法时展示校验错误。
  - 已有相同请求正在处理时展示冲突或返回已有任务信息。
  - 计算失败时可在后续查询中看到失败状态和原因。
- 约束：重算不阻塞页面等待最终计算结果。

#### FR-013：查看健康快照历史（P1）

- 用户可以按时间范围查看 Portfolio 健康快照历史。
- 输入：时间范围、分页参数。
- 输出：快照列表、健康状态、健康分数、计算时间、风险摘要和来源引用。
- 异常处理：
  - 无快照时展示空状态和重算入口。
  - 查询失败时展示统一错误码、错误信息和 request_id。

#### FR-014：查看成本汇总（P0）

- 用户可以查看 Portfolio 在指定时间范围内的成本汇总。
- 输入：时间范围、快照标识。
- 输出：总成本、按项目汇总、按模型汇总、来源引用、计算时间和数据时间范围。
- 异常处理：
  - 无成本数据时展示空状态，不展示虚假金额。
  - 来源数据不足或失败时展示缺失说明或错误态。
- 约束：成本汇总复用已有 LLMCallLog / 成本能力，不新增独立成本账本。

### 前端页面与交互

#### FR-015：实现 Portfolio 管理页面（P0）

- 用户可以通过系统级导航进入 `/portfolios`，完成列表查看、新增组合、筛选、分页、详情跳转等操作。
- 输入：页面筛选条件和新增表单信息。
- 输出：列表、空态、加载态、错误态、成功反馈和跳转结果。
- 异常处理：接口失败时展示统一错误码、错误信息和 request_id。

#### FR-016：实现 Portfolio 详情页面（P0）

- 用户可以访问 `/portfolios/:portfolioId` 查看组合详情、成员概览、健康摘要、成本摘要和策略摘要。
- 输入：Portfolio 标识。
- 输出：详情信息、摘要卡片、成员入口、健康 / 成本入口。
- 异常处理：不存在、无权限、加载失败、摘要数据不足时均展示清晰状态。

#### FR-017：实现项目优先级页面（P0）

- 用户可以访问 `/portfolios/:portfolioId/projects` 查看成员列表、加入项目、移除项目、调整优先级和权重。
- 输入：成员筛选条件、加入项目表单、优先级调整表单、移除原因。
- 输出：成员列表、操作成功反馈、刷新后的成员数据。
- 异常处理：表单校验失败、重复加入、无权限、成员不存在等场景展示明确错误。

#### FR-018：实现健康 / 成本汇总页面（P0）

- 用户可以访问 `/portfolios/:portfolioId/health` 查看健康、风险、成本、历史快照和来源信息。
- 输入：时间范围、快照标识、重算动作。
- 输出：健康状态、风险项、成本汇总、历史快照、来源引用、重算任务反馈。
- 异常处理：数据不足展示 unknown 和缺失来源；接口失败展示统一错误结构。

#### FR-019：接入可点击原型与真实管理台渲染（P0）

- Portfolio 相关页面必须基于需求原型中的 Portfolio 管理入口和页面布局实现。
- 输入：用户从侧边栏或首页点击 Portfolio 入口，并操作页面按钮、筛选、表单、详情跳转。
- 输出：具备统一 AppLayout、导航高亮、卡片、表格、表单、弹窗、状态标签、Toast / Alert 的真实管理台页面。
- 异常处理：页面刷新后不得 404；CSS 或 JS 不可用时不满足验收。

## 3. Non-Functional Requirements

### NFR-001：统一 API 响应与错误展示（P0）

所有前后端交互必须遵循统一响应结构。失败态必须向用户展示错误码、错误信息和 request_id，便于定位问题。

### NFR-002：权限与安全（P0）

Portfolio、成员项目、健康摘要、成本摘要和策略摘要均必须受用户权限约束。用户不得看到无权限项目的敏感信息。接口必须使用授权请求，输入必须校验。

### NFR-003：审计与可追踪（P0）

所有 Portfolio 和成员关系的变更必须可追踪，包括创建、编辑、加入项目、移除项目、调整优先级、调整权重和触发健康快照重算。

### NFR-004：幂等与重复提交处理（P0）

创建 Portfolio、加入项目、移除项目、调整优先级和触发健康快照重算等变更或触发类动作必须避免重复提交造成重复数据或状态错乱。

### NFR-005：数据来源可解释（P0）

健康、成本、策略摘要必须展示 date_range、calculated_at 和 source_refs。数据不足时必须明确展示 unknown 或缺失来源，不得伪造结论。

### NFR-006：前端状态完整性（P0）

Portfolio 相关页面必须覆盖加载态、空态、错误态、成功态。页面刷新后可直接访问，当前导航高亮或当前位置提示必须保留。

### NFR-007：原型一致性与可交互性（P0）

前端页面必须按原型实现主要视觉层级和交互，不得出现浏览器默认裸 HTML。导航、筛选、分页、表单提交、弹窗、详情跳转、状态操作必须可点击并有反馈。

### NFR-008：内容类型无关（P0）

Core 层和 Portfolio 资源命名不得使用 Novel / Book / Chapter 作为核心概念。Portfolio 只能聚合 ContentProject 和相关通用状态。

## 4. 验收标准

### Portfolio 管理

- AC-001：用户可以从系统级导航进入 Portfolio 管理页，页面不是空白页、占位页或裸 HTML。
- AC-002：Portfolio 列表支持分页、筛选和排序；无数据时展示空状态和新增入口。
- AC-003：用户可以成功新增 Portfolio，成功后看到反馈并能在列表或详情中看到新组合。
- AC-004：新增或编辑 Portfolio 时，必填项缺失、格式不合法、冲突、无权限等错误会展示统一错误信息和 request_id。
- AC-005：用户可以编辑 Portfolio 信息，成功后页面展示更新后的内容。

### Portfolio 详情

- AC-006：用户可以从列表进入 Portfolio 详情页，详情页刷新后仍可访问且不出现 404。
- AC-007：详情页展示组合基本信息、项目数量、健康摘要、成本摘要和策略摘要。
- AC-008：Portfolio 不存在、无权限或摘要数据不足时，详情页展示对应状态，不使用列表缓存伪造详情。
- AC-009：策略建议摘要仅提供查看和跳转，不提供绕过人工确认的执行入口。

### 成员与优先级

- AC-010：用户可以向 Portfolio 加入已有项目，并设置优先级、权重、角色和备注。
- AC-011：同一 Portfolio 内重复加入同一项目会返回明确冲突或幂等结果，不产生重复有效成员关系。
- AC-012：用户可以查看 Portfolio 成员列表，并按分页、优先级、状态和排序条件查询。
- AC-013：用户可以调整项目优先级和权重，成功后看到更新后的成员数据和操作成功反馈。
- AC-014：调整优先级或权重不会自动改变项目状态、暂停项目或执行策略建议。
- AC-015：用户可以从 Portfolio 移除项目，移除后成员列表更新，但 ContentProject 本身不被删除且项目状态不改变。
- AC-016：成员新增、移除、优先级调整、权重调整均产生可追踪的操作记录。

### 健康与成本

- AC-017：用户可以查看 Portfolio 健康汇总，页面展示健康状态、健康分数、风险摘要、时间范围、计算时间和来源引用。
- AC-018：数据不足时健康状态展示 unknown，并说明缺失来源，不展示虚假健康结论。
- AC-019：用户可以触发健康快照重算，页面立即得到快照标识或任务标识，并提示后续查询方式。
- AC-020：用户可以查看健康快照历史；无历史快照时展示空状态和重算入口。
- AC-021：用户可以查看成本汇总，包含总成本、按项目汇总、按模型汇总、时间范围、计算时间和来源引用。
- AC-022：无成本数据或来源数据不足时，页面展示空态或缺失说明，不展示虚假金额。

### 前端页面与原型

- AC-023：`/portfolios`、`/portfolios/:portfolioId`、`/portfolios/:portfolioId/projects`、`/portfolios/:portfolioId/health` 均可直接访问，刷新后不出现 404。
- AC-024：Portfolio 页面接入系统级导航，用户不需要手输 URL 才能访问核心页面。
- AC-025：当前 Portfolio 路由有导航高亮或当前位置提示。
- AC-026：页面加载态、空态、错误态、成功态均可见且样式化展示。
- AC-027：主要按钮、筛选、分页、表单提交、弹窗、详情跳转、重算动作均可点击并有反馈。
- AC-028：接口失败态展示 error.code、error.message 和 request_id。
- AC-029：页面视觉结构、信息层级、卡片、表格、表单、弹窗、状态标签与原型基准保持一致；如有偏差，以接口契约为准并说明原因。
- AC-030：e2e 或集成测试覆盖从导航入口进入页面、触发主要按钮、展示接口成功结果和展示接口失败态。

### 系统边界

- AC-031：Core 层没有引入 Novel / Book / Chapter 作为 Portfolio 核心资源命名。
- AC-032：Portfolio 不创建 ContentItem、不触发 WorkflowRun、不直接调用 AgentRuntime。
- AC-033：Portfolio 成本汇总复用 LLMCallLog / 成本汇总能力，不新增独立成本账本。
- AC-034：Portfolio 健康与策略摘要只读聚合已有项目状态、发布状态、MetricRecord、LLMCallLog、StrategySuggestion 等来源。
- AC-035：本迭代不引入 n8n 核心编排。

## 5. Out of Scope

- 不实现超出 Portfolio 管理、详情、成员优先级、健康 / 成本汇总页面之外的新业务功能。
- 不创建 ContentItem，不触发 WorkflowRun，不直接调用 AgentRuntime。
- 不自动暂停项目、不自动改变项目状态、不自动执行策略建议。
- 不在 Portfolio 中实现策略建议的确认、忽略或执行流程；这些动作继续由策略建议功能负责。
- 不新增独立成本账本，不重复保存 LLMCallLog 或 MetricRecord 的事实数据。
- 不重建指标中心、策略引擎、发布队列或平台 Adapter。
- 不引入 n8n 作为核心编排或核心状态保存位置。
- 不使用 Novel / Book / Chapter 作为 Core Portfolio 资源命名。
- 不实现未定义接口的隐式前端调用。

## 6. 依赖说明

- 依赖 ContentProject / ContentType：Portfolio 成员以已有项目为对象，不重新定义项目生命周期。
- 依赖 WorkflowRun、Schedule、ProductionPlan、LLMCallLog：健康与成本汇总读取运行状态、失败记录和模型成本，不触发核心工作流。
- 依赖 PublishJob：发布阻塞、待发布、待回填数量可作为风险来源。
- 依赖 MetricRecord：健康趋势、缺失数据和表现指标从指标中心读取，不重复保存指标事实。
- 依赖 StrategySuggestion：Portfolio 展示策略建议摘要和待处理数量，但策略确认、忽略、执行仍由策略建议功能处理。
- 依赖统一 API 契约：所有接口响应、错误、分页、鉴权、request_id、幂等和 OpenAPI 要求遵循项目 API 契约规范。
- 依赖原型文件：Portfolio 页面以 `docs/requirements/ai-content-factory-clickable-prototype.html` 中的 Portfolio 管理入口和相关交互为前端实现基准。
