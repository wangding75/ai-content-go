# Iteration 9 PRD：策略建议与单类型业务闭环

## 1. 功能概述

本次迭代面向单项目、单内容类型的数据闭环，在项目工作区提供“策略建议”能力：系统基于已记录的项目指标生成可解释的策略建议，用户可以查看建议列表与详情，并对建议执行确认、忽略、执行、失败重试等人工流转操作。

本迭代包含后端策略建议生成与状态流转接口、执行日志与操作日志追踪、前端策略建议页面/详情页/操作页，以及基于原型的导航入口、页面交互、成功态与失败态展示。

## 2. Functional Requirements

### 策略建议生成

- **FR-001（P0）**：用户必须能在项目工作区触发生成策略建议。输入包括 `project_id`、`date_range`，并可选传入 `rule_codes`、`metric_codes`、`force_regenerate`；输出必须包含 `suggestion_run_id` 或等价运行记录 ID 与初始状态。异常处理：日期范围缺失或非法时返回 `VALIDATION_ERROR`；重复生成且不允许强制生成时返回可解释错误或复用幂等结果。
- **FR-002（P0）**：系统生成建议时必须读取项目已有指标能力，而不是接受前端直接传入的指标结论。输出建议必须关联项目、日期范围、触发规则、生成时间、生成方式和指标快照。异常处理：缺失关键指标、样本量不足或日期范围不足时，必须生成低置信度建议或返回可解释失败原因，不允许输出无法解释的强结论。
- **FR-003（P0）**：每条策略建议必须展示可解释内容，包括建议类型、标题、触发原因、证据指标、影响范围、风险等级、置信度、建议动作和预期收益。输入为建议 ID；输出为完整建议详情。异常处理：建议不存在时返回 `NOT_FOUND`。
- **FR-004（P1）**：建议类型必须使用枚举值，首期至少支持 `keep`、`optimize`、`suspend`、`promote`、`cost_control`。异常处理：未知建议类型不得进入持久化结果或接口响应。

### 策略建议列表与筛选

- **FR-005（P0）**：用户必须能查看某项目的策略建议分页列表。输入支持 `status`、`suggestion_type`、`risk_level`、`confidence`、`date_from`、`date_to`、`page`、`page_size`、`sort`、`order`；输出为统一分页结构的建议列表。异常处理：筛选值非法时返回 `VALIDATION_ERROR`。
- **FR-006（P1）**：策略建议列表必须支持空状态、加载态、错误态和成功态。输出为空时展示可操作空态；接口失败时展示错误码、错误信息和 `request_id`。

### 人工确认与状态流转

- **FR-007（P0）**：用户必须能确认 `pending` 状态的建议。输入为建议 ID、可选 `note` 与 `Idempotency-Key`；输出包括 `suggestion_id`、`previous_status`、`current_status`、`operation_log_id`。异常处理：非 `pending` 状态确认时返回 `CONFLICT`；重复幂等请求返回同一结果。
- **FR-008（P0）**：用户必须能忽略 `pending` 状态的建议。输入为建议 ID、必填 `reason`、可选 `note` 与 `Idempotency-Key`；输出包括 `suggestion_id`、`previous_status`、`current_status`、`operation_log_id`。异常处理：缺少忽略原因返回 `VALIDATION_ERROR`；对终态建议忽略返回 `CONFLICT`。
- **FR-009（P0）**：系统必须强制执行建议状态机：`pending` 可进入 `confirmed` 或 `ignored`，`confirmed` 可进入 `executed` 或 `execution_failed`，`execution_failed` 可重试进入 `executed` 或继续 `execution_failed`，`ignored` 与 `executed` 为终态。异常处理：非法状态流转统一返回 `CONFLICT`。
- **FR-010（P0）**：`confirm` 只表示人工认可建议，不得自动修改项目配置、调度计划、Prompt、模型配置、发布状态或内容生产状态。输出仅体现建议状态变化与操作日志。

### 策略执行与执行日志

- **FR-011（P0）**：用户必须能对 `confirmed` 状态建议发起执行。输入包括 `action_type`、`target_type`、`target_id`、可选 `operator_note` 与 `Idempotency-Key`；输出包括 `execution_log_id`、`suggestion_id`、`previous_status`、`current_status`。异常处理：执行失败时建议进入 `execution_failed` 并记录失败原因。
- **FR-012（P0）**：策略执行必须可追踪，每次执行或执行失败都必须追加 `strategy_execution_log`，记录操作者、执行动作、目标资源、前后状态、结果和失败原因。输出可通过详情页或执行日志接口查看。异常处理：日志查询目标不存在时返回 `NOT_FOUND`。
- **FR-013（P0）**：如执行动作会影响工作流、调度、发布、内容生产、Prompt 或模型配置，策略模块不得直接绕过对应领域边界改写状态；必须通过已有领域接口或后续明确接口完成，并记录目标接口、目标资源和执行结果。异常处理：缺少可用目标接口时执行应失败并展示可解释原因。
- **FR-014（P1）**：用户必须能重试 `execution_failed` 状态的建议执行。输入为建议 ID、可选 `operator_note` 与 `Idempotency-Key`；输出包括新的或幂等复用的 `execution_log_id` 与当前状态。异常处理：非失败状态重试返回 `CONFLICT`。
- **FR-015（P1）**：用户必须能分页查看建议执行日志。输入包括建议 ID、`page`、`page_size`；输出为执行日志分页列表。异常处理：分页参数非法时返回 `VALIDATION_ERROR`。

### 操作审计与统一 API 契约

- **FR-016（P0）**：所有状态变更操作必须写入 `operation_log`，并在响应中返回可追踪的日志标识。异常处理：操作日志写入失败时状态变更不得静默成功。
- **FR-017（P0）**：所有接口必须使用统一响应结构，成功响应包含 `success`、`data`、`error: null`、`request_id`，失败响应包含 `success: false`、`data: null`、统一 `error` 和 `request_id`。
- **FR-018（P0）**：策略确认、忽略、执行、重试执行等状态敏感接口必须支持 `Idempotency-Key`。异常处理：同一幂等键但请求体不一致时返回 `IDEMPOTENCY_CONFLICT`。
- **FR-019（P1）**：所有本迭代接口必须有 Go request/response DTO、参数校验和 OpenAPI 描述。异常处理：请求体、路径参数、查询参数校验失败时返回 `VALIDATION_ERROR`。

### 前端页面与原型交互

- **FR-020（P0）**：项目工作区必须提供“策略建议”导航入口，用户无需手输 URL 即可进入 `/projects/:projectId/strategy-suggestions`。输出为带统一 AppLayout、导航高亮和策略建议列表的页面。异常处理：刷新页面不得 404。
- **FR-021（P0）**：策略建议页必须基于原型实现真实管理台视觉样式，包括卡片、表格、筛选、状态标签、按钮、弹窗或表单，不得是裸 HTML、空白页或占位页。
- **FR-022（P0）**：用户必须能在前端完成生成建议、筛选建议、分页查看、跳转详情、确认、忽略、执行和重试等主要交互。输入来自页面控件；输出为 Toast/Alert、页面数据刷新或详情跳转。异常处理：接口失败时展示错误码、错误信息和 `request_id`。
- **FR-023（P0）**：建议详情页 `/strategy-suggestions/:suggestionId` 必须展示建议原因、影响范围、证据指标、`metrics_snapshot`、状态、置信度、风险说明和执行记录摘要。异常处理：建议不存在或接口失败时展示样式化失败态。
- **FR-024（P1）**：建议操作页 `/strategy-suggestions/:suggestionId/actions` 必须提供确认、忽略、执行或重试执行的操作入口，并按当前状态禁用不合法动作。异常处理：表单字段缺失或状态冲突时展示对应错误反馈。

## 3. Non-Functional Requirements

- **NFR-001（P0）API 兼容性**：本迭代所有 API 必须遵循 `/api/v1` REST JSON 规范、统一响应结构、统一错误码、分页结构和 OpenAPI 必填字段。
- **NFR-002（P0）可追溯性**：策略建议必须能追溯到项目、日期范围、触发规则、指标快照、生成方式、操作日志和执行日志。
- **NFR-003（P0）安全与权限**：API 必须保留 Bearer Token 鉴权契约；状态变更接口不得在无认证上下文下设计为匿名操作。
- **NFR-004（P0）幂等性**：确认、忽略、执行、重试执行等状态变更必须支持幂等，避免重复提交导致重复状态变更或重复跨模块执行。
- **NFR-005（P0）领域边界**：Core 层不得引入 Novel、Book、Chapter 等内容类型专属资源命名；策略模块不得绕过其他领域服务边界直接改写跨模块状态。
- **NFR-006（P0）异步响应**：生成建议等触发型操作不得阻塞 HTTP 请求等待最终处理完成，必须返回运行记录 ID、任务 ID 或业务记录 ID 供后续查询。
- **NFR-007（P1）前端可用性**：页面必须加载统一样式与 JS 交互，支持空态、加载态、错误态、成功态，并在失败态展示 `request_id`。
- **NFR-008（P1）可测试性**：后端接口、状态机、幂等行为、日志追加、非法流转、前端导航进入、主要交互和失败态必须可被自动化测试覆盖。

## 4. 验收标准

- **AC-001（对应 FR-001/FR-002）**：从策略建议页触发生成建议后，接口立即返回 `suggestion_run_id` 或等价运行记录 ID；生成结果包含项目、日期范围、触发规则和指标快照。
- **AC-002（对应 FR-002/FR-003）**：指标缺失、样本不足或日期范围不足时，系统返回可解释失败原因或低置信度建议，不生成无法解释的强结论。
- **AC-003（对应 FR-003/FR-004）**：建议详情中可查看建议类型、触发原因、证据指标、影响范围、风险等级、置信度、建议动作和预期收益，且建议类型属于约定枚举。
- **AC-004（对应 FR-005/FR-006）**：建议列表支持分页、状态筛选、类型筛选、风险等级筛选、置信度筛选、日期筛选、排序；空态与失败态可正确渲染。
- **AC-005（对应 FR-007/FR-008/FR-009）**：`pending` 建议可以确认或忽略；非法状态流转返回 `CONFLICT`；忽略缺少原因返回 `VALIDATION_ERROR`。
- **AC-006（对应 FR-010）**：确认建议后只改变建议状态并记录日志，不修改项目配置、调度计划、Prompt、模型配置、发布状态或内容生产状态。
- **AC-007（对应 FR-011/FR-014）**：`confirmed` 建议可以执行，执行成功进入 `executed`，执行失败进入 `execution_failed`；失败建议可以重试并追加执行日志。
- **AC-008（对应 FR-012/FR-015）**：详情页或执行日志接口能分页查看每次执行尝试，包含动作、目标、操作者、前后状态、结果和失败原因。
- **AC-009（对应 FR-013）**：涉及跨模块变更的策略执行不直接改写其他模块状态；验收可看到调用目标接口或失败原因记录。
- **AC-010（对应 FR-016）**：所有确认、忽略、执行、重试执行操作均写入 `operation_log`，响应返回 `operation_log_id` 或可追踪日志标识。
- **AC-011（对应 FR-017/FR-019）**：所有接口均符合统一响应结构并进入 OpenAPI，失败响应包含统一错误码、错误信息、详情和 `request_id`。
- **AC-012（对应 FR-018）**：重复提交相同 `Idempotency-Key` 返回同一结果；同一幂等键请求体不一致返回 `IDEMPOTENCY_CONFLICT`。
- **AC-013（对应 FR-020/FR-021）**：用户可以从项目工作区导航进入策略建议页；页面刷新不 404，并显示统一布局、导航高亮、卡片/表格/按钮/状态标签样式。
- **AC-014（对应 FR-022/FR-024）**：前端主要按钮和表单可点击并有反馈；不合法动作禁用或展示状态冲突错误；成功后显示反馈并刷新数据。
- **AC-015（对应 FR-023）**：建议详情页直接访问可用，能够展示完整建议解释与执行记录摘要；接口失败时展示错误码、错误信息和 `request_id`。
- **AC-016（对应 NFR-005）**：新增资源、接口和页面文案不把 Novel / Book / Chapter 作为 Core 资源命名；仅可在示例内容或内容包上下文中出现。
- **AC-017（对应 NFR-008）**：自动化测试覆盖后端状态机、幂等、日志追加、非法流转，以及前端导航进入、主要交互、接口成功渲染和失败态展示。

## 5. Out of Scope

- 不做多项目 Portfolio 级策略排序、组合健康分析和跨项目资源分配。
- 不做自动改写 Prompt、模型配置、调度计划或项目状态的隐式执行。
- 不做绕过 WorkflowRun、AgentTask、LLMCallLog 或其他领域服务的核心生产链路。
- 不做 n8n 核心编排或把策略状态机保存在 n8n execution 中。
- 不做没有指标依据、没有证据快照的黑盒策略建议。
- 不做超出策略建议页、建议详情页、建议操作页范围的额外业务页面。
- 不做未定义接口的隐式前端调用。
- 不做跨内容类型或跨项目的策略闭环。

## 6. 依赖说明

- 依赖 ContentProject / ContentType 作为项目与内容类型边界。
- 依赖 MetricRecord / MetricTemplate 或等价指标汇总能力作为策略建议主要输入。
- 如策略生成使用 Agent 或 LLM 文案解释，必须记录 AgentTask / LLMCallLog。
- 如策略执行涉及内容生产、工作流、调度、发布或模型配置，必须通过对应领域接口完成，不在策略模块内直接改写其他模块状态。
