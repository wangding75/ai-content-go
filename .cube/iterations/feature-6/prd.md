# Iteration 6 PRD：Knowledge Memory 记忆系统

## 1. 功能概述

本次迭代建立项目级 Knowledge Memory 记忆系统，让内容项目能够沉淀长期知识、维护动态状态、预览上下文装配结果，并对内容连续性与一致性进行检查。

本迭代同时交付前端与后端产品能力：

- 后端提供项目级记忆读取、人工修正、动态状态更新、上下文装配快照、一致性报告创建与查询能力。
- 前端在项目工作区新增记忆上下文、一致性报告、上下文预览页面，并接入项目导航、真实接口、统一状态反馈与原型化视觉交互。
- 所有能力必须保持 Core 内容类型无关，不得将 Novel / Book / Chapter 作为核心资源命名。

## 2. Functional Requirements

### 2.1 项目级记忆上下文

- **FR-001（P0）查看项目记忆上下文**
  - 功能描述：用户在项目工作区进入“记忆上下文”页面后，可以查看当前项目的 StaticContext、DynamicState、RecentContentWindow 策略和 StyleGuide。
  - 输入：项目 ID。
  - 输出：当前项目记忆内容、版本、更新时间、最近快照摘要。
  - 异常处理：项目不存在时展示 `NOT_FOUND`；无权限时展示 `FORBIDDEN`；接口失败时展示错误码、错误信息和 `request_id`。

- **FR-002（P0）人工修正 StaticContext**
  - 功能描述：用户可以编辑项目长期稳定资料，例如世界观摘要、人物设定摘要、禁用规则、风格规则摘要等。
  - 输入：StaticContext 修正内容、修正说明。
  - 输出：新版本号、操作日志 ID、成功反馈。
  - 异常处理：内容为空或格式不合法时展示 `VALIDATION_ERROR`；版本冲突时展示 `CONFLICT`；失败时不得丢失用户已输入内容。

- **FR-003（P0）人工修正 StyleGuide**
  - 功能描述：用户可以维护内容风格、语气、叙事约束、禁用表达等通用风格信息，供后续生成和审稿复用。
  - 输入：StyleGuide 修正内容、修正说明。
  - 输出：新版本号、操作日志 ID、成功反馈。
  - 异常处理：内容为空或格式不合法时展示 `VALIDATION_ERROR`；版本冲突时展示 `CONFLICT`；失败时展示 `request_id` 并允许重试。

- **FR-004（P1）查看记忆快照列表**
  - 功能描述：用户可以在记忆页面查看该项目的上下文装配、动态状态更新或人工纠偏产生的快照列表。
  - 输入：项目 ID、可选内容单元 ID、分页参数。
  - 输出：快照列表、来源、Token 预算、估算 Token、截断策略、创建时间、分页信息。
  - 异常处理：无快照时展示空态；分页参数不合法时展示 `VALIDATION_ERROR`。

- **FR-005（P0）人工纠偏 DynamicState**
  - 功能描述：用户可以对 DynamicState 做纠偏、补充或覆盖说明，但不能把 DynamicState 当作普通文本自由编辑；DynamicState 主来源仍是内容版本、审稿报告、内容单元生成结果和一致性检查结果。
  - 输入：项目 ID、纠偏原因 `reason`、变更内容 `changes`、来源引用 `source_refs`。
  - 输出：记忆快照 ID、动态状态版本号、操作日志 ID、成功反馈。
  - 异常处理：缺少 reason、changes 或 source_refs 时展示 `VALIDATION_ERROR`；来源引用无效时展示 `VALIDATION_ERROR`；版本冲突时展示 `CONFLICT`；失败时保留用户输入。

- **FR-006（P1）配置 RecentContentWindow 最小策略**
  - 功能描述：用户可以配置最近内容窗口的最小可用策略，包括最近内容数量、Token 上限和超限截断方式。
  - 输入：项目 ID、`item_count`、`token_limit`、`truncation_policy`。
  - 输出：更新后的 RecentContentWindow 策略、版本号、操作日志 ID。
  - 异常处理：数量或 Token 上限不合法时展示 `VALIDATION_ERROR`；不支持的截断策略展示 `VALIDATION_ERROR`。

### 2.2 动态状态更新与上下文装配

- **FR-007（P0）更新内容单元动态状态**
  - 功能描述：系统或用户触发动态状态更新时，可以基于内容单元摘要、变更说明和可信版本来源更新项目 DynamicState。
  - 输入：内容单元 ID、摘要、变更项、来源版本 ID。
  - 输出：记忆快照 ID、动态状态版本号。
  - 异常处理：内容单元不存在时展示 `NOT_FOUND`；来源版本无效时展示 `VALIDATION_ERROR`；重复提交不得产生冲突快照。

- **FR-008（P0）装配上下文并生成快照**
  - 功能描述：用户或后续 Agent 任务可以按用途和预算触发上下文装配，系统按 StaticContext、StyleGuide、DynamicState、RecentContentWindow、当前任务输入的顺序组织上下文，并生成可追踪快照。
  - 输入：项目 ID、用途、Token 预算、可选内容单元 ID。
  - 输出：上下文快照 ID、估算 Token、截断策略、装配摘要。
  - 异常处理：预算不合法时展示 `VALIDATION_ERROR`；项目不存在时展示 `NOT_FOUND`；相同幂等请求不得生成重复冲突结果。

- **FR-009（P0）预览上下文装配结果**
  - 功能描述：用户在“上下文预览”页面可以先执行“预览上下文”动作，查看来源、预算、截断策略和预览文本；预览动作不落库。
  - 输入：项目 ID、用途、Token 预算、可选内容单元 ID。
  - 输出：上下文来源列表、Token 预算、估算 Token、截断策略、预览文本。
  - 异常处理：无可用来源时展示空态和说明；接口失败时展示统一错误结构和 `request_id`。

- **FR-010（P0）从预览页生成上下文快照**
  - 功能描述：用户在“上下文预览”页面确认预览结果后，可以点击“生成上下文快照”调用装配接口并落库生成 `context_snapshot_id`。
  - 输入：项目 ID、用途、Token 预算、可选内容单元 ID、幂等键。
  - 输出：上下文快照 ID、估算 Token、截断策略、成功反馈。
  - 异常处理：重复点击不得生成冲突快照；生成失败时展示错误码、错误信息和 `request_id`。

### 2.3 一致性报告

- **FR-011（P0）创建一致性检查报告**
  - 功能描述：用户可以从项目工作区触发一致性检查，检查设定一致性、状态连续性、风格一致性、人物关系、未解决伏笔等问题。
  - 输入：项目 ID、检查范围、检查作用域、严重级别阈值。
  - 输出：报告 ID、初始状态。
  - 异常处理：检查范围为空或不合法时展示 `VALIDATION_ERROR`；重复提交不得创建重复报告；异步执行失败时报告状态应可查询。

- **FR-012（P0）查看一致性报告列表**
  - 功能描述：用户可以在“一致性报告”页面查看报告列表、状态、问题数量、严重级别汇总，并支持筛选、排序和分页。
  - 输入：项目 ID、状态筛选、分页、排序参数。
  - 输出：报告列表、状态、问题数量、严重级别汇总、分页信息。
  - 异常处理：无报告时展示空态；筛选无结果时展示筛选空态；接口失败时展示错误码、错误信息和 `request_id`。

- **FR-013（P0）查看独立一致性报告详情页**
  - 功能描述：用户可以从列表页进入独立详情页 `/projects/:projectId/consistency-reports/:reportId`，查看报告详情和结构化问题项；列表页只负责展示报告列表、状态、创建时间、问题数量和入口按钮。
  - 输入：项目 ID、报告 ID。
  - 输出：报告详情、问题项列表、来源快照、建议处理方式。
  - 异常处理：报告不存在时展示 `NOT_FOUND`；报告仍在执行时展示进行中状态和刷新入口；问题项为空时展示通过状态。

- **FR-014（P0）一致性报告状态流转与结构化结果**
  - 功能描述：一致性检查至少支持 `pending`、`running`、`completed`、`failed` 状态；验收必须能看到 `completed` 报告和结构化 issues，但不强制真实 LLM 高质量检查效果。
  - 输入：报告创建请求、异步执行结果或确定性规则生成结果。
  - 输出：可查询的状态流转、completed 报告、结构化问题项。
  - 异常处理：执行失败时进入 `failed` 并展示失败原因；无问题时 completed 报告 issue_count 为 0。

- **FR-015（P0）结构化一致性问题项**
  - 功能描述：报告详情中的每个 issue 必须是结构化对象，便于前端展示和后续策略引用。
  - 输入：一致性检查结果。
  - 输出：至少包含 `issue_id`、`severity`、`type`、`title`、`description`、`affected_content_items`、`suggestion`。
  - 异常处理：不得只返回不可解析的长文本；字段缺失时报告结果视为不可用。

### 2.4 前端页面与交互

- **FR-016（P0）项目工作区导航接入**
  - 功能描述：用户可以从项目工作区导航进入“记忆上下文”“一致性报告”“上下文预览”页面，不需要手输 URL。
  - 输入：用户点击项目工作区导航。
  - 输出：进入对应页面，当前导航项高亮或显示当前位置提示。
  - 异常处理：页面刷新后不得 404；项目 ID 无效时展示项目不存在错误。

- **FR-017（P0）原型化页面渲染**
  - 功能描述：新增页面必须参考可点击原型实现管理台视觉样式、信息层级、卡片、表格、表单、弹窗、状态标签和主要交互。
  - 输入：用户访问新增页面并执行主要操作。
  - 输出：页面具备统一 AppLayout、CSS 样式和可执行 JS 交互。
  - 异常处理：不得出现浏览器默认裸 HTML；按钮、筛选、分页、提交、弹窗、详情跳转必须有反馈。

- **FR-018（P0）页面状态反馈闭环**
  - 功能描述：每个新增页面必须支持加载态、空态、错误态、成功态，并在操作成功后刷新关联数据或提示下一步。
  - 输入：页面加载、接口成功、接口失败、表单提交、异步触发。
  - 输出：对应状态 UI、Toast 或 Alert 反馈、统一错误展示。
  - 异常处理：失败态必须展示 `error.code`、`error.message`、`request_id`。

### 2.5 API 与契约可用性

- **FR-019（P0）后端接口支撑前端主要操作**
  - 功能描述：后端必须提供记忆读取、StaticContext 修正、StyleGuide 修正、DynamicState 纠偏、RecentContentWindow 最小策略配置、快照列表、上下文预览、上下文装配、动态状态更新、一致性报告创建、列表和详情查询能力，使前端页面可完成真实联调。
  - 输入：来自前端页面的查询、编辑、预览、触发和详情请求。
  - 输出：统一响应结构、统一错误结构、分页结构、业务记录 ID 或状态信息。
  - 异常处理：所有失败响应必须包含错误码、错误信息和 `request_id`；异步触发不得同步等待最终结果。

- **FR-020（P0）操作日志与状态追踪**
  - 功能描述：所有人工修正、动态状态纠偏、RecentContentWindow 策略配置、上下文装配、一致性检查创建等状态变更必须形成可追踪记录，便于后续审计和排查。
  - 输入：用户或系统发起的状态变更动作、说明或原因。
  - 输出：操作日志 ID、业务记录 ID、状态或版本信息。
  - 异常处理：状态流转不合法时展示 `CONFLICT`；日志写入失败时操作不得伪成功。

## 3. Non-Functional Requirements

- **NFR-001（P0）内容类型无关性**：Core 能力只能使用 project、content_item、memory、snapshot、report 等通用概念，不得在核心命名中引入 Novel / Book / Chapter。
- **NFR-002（P0）安全与鉴权**：所有接口必须要求 Bearer Token；无权限访问时返回统一错误结构。
- **NFR-003（P0）幂等性**：上下文装配、动态状态更新、动态状态纠偏、一致性报告创建等重复提交风险高的动作必须支持幂等，避免页面重试产生重复快照或报告。
- **NFR-004（P0）可审计性**：人工修正、人工纠偏与状态变更必须记录操作日志；上下文快照必须记录来源、预算、截断策略和触发来源。
- **NFR-005（P0）前端可用性**：新增页面必须加载 CSS、具备 JS 交互、支持刷新直达、导航高亮和统一错误展示。
- **NFR-006（P1）Token 预算控制**：上下文装配必须展示预算、估算 Token 和截断策略，避免上下文无限膨胀。
- **NFR-007（P1）可测试性**：新增前端页面至少覆盖导航进入、主要按钮点击、接口成功渲染、接口失败渲染；后端能力需能被接口和服务测试验证。
- **NFR-008（P1）确定性验收**：一致性检查验收允许使用确定性规则或测试数据生成 completed 报告和结构化 issues，不要求真实 LLM 输出达到生产质量。

## 4. 验收标准

- **AC-001 对应 FR-001**：进入项目“记忆上下文”页面后，可以看到 StaticContext、DynamicState、RecentContentWindow 策略、StyleGuide、版本和更新时间；接口失败时展示 `request_id`。
- **AC-002 对应 FR-002 / FR-003**：用户可以提交 StaticContext 和 StyleGuide 修正，成功后显示新版本号和操作日志 ID；失败时保留输入内容。
- **AC-003 对应 FR-004**：记忆快照列表支持分页展示来源、Token、截断策略和创建时间；无数据时显示空态。
- **AC-004 对应 FR-005**：用户可以通过专门纠偏动作提交 reason、changes、source_refs 修正 DynamicState，成功后返回记忆快照 ID、动态状态版本和操作日志 ID；页面不提供 DynamicState 自由文本编辑。
- **AC-005 对应 FR-006**：用户可以配置 RecentContentWindow 的 item_count、token_limit、truncation_policy；不支持复杂权重、多策略模板、按 Agent 单独配置或自动调参。
- **AC-006 对应 FR-007**：动态状态更新成功后返回记忆快照 ID和动态状态版本；无效内容单元返回统一错误。
- **AC-007 对应 FR-008 / FR-009 / FR-010**：用户可以输入用途和预算预览上下文；预览不落库；点击“生成上下文快照”后生成 context_snapshot_id；页面展示来源、预算、估算 Token、截断策略和预览摘要。
- **AC-008 对应 FR-011**：用户可以触发一致性检查，立即获得报告 ID 和初始状态，不阻塞等待最终检查完成。
- **AC-009 对应 FR-012 / FR-013**：一致性报告列表页展示报告列表、状态、创建时间、问题数量和详情入口；详情通过 `/projects/:projectId/consistency-reports/:reportId` 独立页面展示。
- **AC-010 对应 FR-014 / FR-015**：验收必须能看到 completed 报告和结构化 issues；issue 至少包含 issue_id、severity、type、title、description、affected_content_items、suggestion。
- **AC-011 对应 FR-016**：项目工作区导航包含记忆上下文、一致性报告、上下文预览入口；刷新页面后可直接访问且导航状态正确。
- **AC-012 对应 FR-017 / FR-018**：新增页面不是裸 HTML，具备管理台样式、卡片、表格、表单、按钮、弹窗或反馈组件；加载态、空态、错误态、成功态均可触发或验证。
- **AC-013 对应 FR-019 / FR-020**：前端主要操作均能映射到后端接口；状态变更返回业务记录或操作日志 ID；失败响应遵循统一错误结构。
- **AC-014 对应 NFR-001**：后端核心模块、接口路径、前端通用页面文案中不以 Novel / Book / Chapter 作为 Knowledge Memory 的核心资源名。
- **AC-015 对应 NFR-003 / NFR-004**：重复提交上下文装配、动态状态更新、动态状态纠偏、一致性报告创建不会产生冲突重复结果，并可通过快照或日志追踪来源。
- **AC-016 对应 NFR-007 / NFR-008**：e2e 或集成测试覆盖从项目导航进入新增页面、触发主要操作、展示成功结果和统一错误态；一致性报告可用确定性规则或测试数据完成验收。

## 5. Out of Scope

- 不在本迭代实现真实正文修复或自动改写内容正文。
- 不在本迭代新增超出记忆上下文、一致性报告、上下文预览范围的业务页面。
- 不在本迭代让 n8n 承载记忆装配、一致性检查或核心 Agent 编排。
- 不在 Core 层引入 Novel / Book / Chapter 等小说专属核心资源。
- 不绕过 WorkflowRun / AgentTask / LLMCallLog 完成核心生产链路。
- 不使用只可手输 URL 访问的临时页面替代项目工作区导航入口。
- 不做复杂向量检索 / RAG 系统。
- 不做长期记忆自动优化算法。
- 不做多 Agent 个性化记忆策略。
- 不做完整知识图谱。
- 不保证高质量 LLM 一致性审校效果。
- 不做复杂 RecentContentWindow 策略模板。
- 不做多人协同编辑或复杂版本对比 UI。

## 6. 依赖说明

- 依赖项目与内容基础能力：ContentProject、ContentType、ContentItem。
- 依赖内容生产与审稿产物：generation_run、content_version、review_report 可作为 RecentContentWindow、DynamicState 和一致性检查输入。
- 依赖统一 API 契约：`/api/v1`、统一响应结构、统一错误结构、分页结构、Bearer Token、`Idempotency-Key`。
- 依赖现有 Web Admin 项目工作区导航与全局样式体系。
- 依赖原型文件中的记忆上下文、一致性报告、上下文预览页面作为前端布局和交互基准。
